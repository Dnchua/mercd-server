## 3. 剧情章节 ↔ 地方 ↔ 话数的对应关系【原服观测 + 剧情库】

「11 章剧情」是**剧本打包单位**，不是关卡单位：

- 剧情库（`server/assets/cn350/stories/`）chapter_id = 1,2,5,11,16,21,31,35,40,46,56 + 最终章，共 11 章；CN3.5 可见 533 话（第 11 章开放 30 话，story_id 1865–1894）。
- 每话 story 带 `area_id`（全球连续 1–106）与 `quest_id`；**每个关卡区域挂 5 话**（4 关的战斗前后剧情 + 1 话区域尾声纯剧情），第 1 章另有 3 话序章（area_id=0）。
- stage 与话数：stage N = 区域 4N-3..4N = 每区 5 话 ≈ 20 话（yugalab 摘要一致：エノ=1-23 话含序章）。
- 章边界（约 50 话/章）**会切在 stage 中间**，例：第 1 章含 stage1+stage2+stage3 前半；第 11 章只含区域 101–106（stage 26 全部 + stage 27 前两区）。

## 5. 战斗背景机制与原服取值【原服观测 + 客户端源码】

**机制**（doc05 §2.7）：客户端用 `quest.background_id` + 波次 `timezoneId` 拼资源键 `background/background<id>_<tz>`；`timezone_table`（execute 回包顶层）按波次给时段 id（包内 `_1/_2/_3` ≈ 朝/昼/夜【推断】）。`quest.background` map 携带 3 层视差参数（width/scroll_rate/image_y/image_z/scroll_auto_speed…），原服各关该 map 均相同（568+568+480 三层）。

**原服主线 background_id 实际用到的值**（432 关统计）：`1,2,3,4,5,6,7,8,11,22,31,39,40,47,57,58,68,69,74,81,82` —— 共 21 种，大致按地貌分配（例：a85–a92 观光都市区=68/69 街道与室内剧场，a49 采掘场=40/39，a56–a60 森昂山/湖=47 花海，a73–a83 降雾遗迹=57/58 雾系，a101–a108 利斯坦德=74/81/82）。同一区域内个别关（尤其区域末关 Boss 关）会切图。

**资源缺口**（`inputs/files/background/` 对照）：

| 缺文件 id | 原服用途 |
|---|---|
| `background1/2/3/7` | **前 10 个地方的主用战场**（共 200+ 关引用）—— `inputs/files` 缺，但 `client/decoded/assets/unity/background/` 内**三时段齐全**（APK 内置），可补入 |
| `background81/82` | 利斯坦德山地/遗迹（stage 26–27，q1361+）—— **全位置缺失** |
| `background80/84/85` | 活动 44 关（q1440–1451 用 84/85）【doc17 已记】—— **全位置缺失** |
| `background100000–100010` | 活动专用战场（在库，未被主线引用） |

另：`area/area_1..5`（stage1–2 前 5 个区域缩略图）在 `inputs/files` 缺、`client/decoded` 有；`area_101..108`（stage 26–27）与 `area_4176..4178`（活动 44）**两处都缺**。

→ 即使把 `BackgroundPool` 改成按表固定，仍有 `background80/81/82/84/85` 五个包全位置缺失；bg1/2/3/7 可从 `client/decoded` 直接补入。缺失包需找回（国服客户端更新包/其他资源备份），或临时映射到已存在的近似包并标注**重建值**。

**时段（timezone_table）**：主线 quest 的 execute 回包没有录播，逐波时段是**缺口**；`/areas` 列表包不含此字段。剧情场景 `timezone` 字段多为 `2`（昼）可作弱参考。建议先全按 `tz=1`（或按剧情场景时段）下发，标注【重建值】。

**时段收益（2026-11-24 补，原服观测）**：mlk 录播 execute 的每怪掉落按波次时段变化——朝 tz=1 金币 36.8 / 资材 12.1（q1359、q1361），夕 tz=2 43.9 / 14.0（q1360 第 2、3 波，≈×1.19），夜 tz=3 72.5 / 23.0（q1357，`rush_mode=mode_70`，≈×1.97）；q80 极难夕 3805 → 夜 6343（=2.0/1.2）。经验与 SP 不变。夜晚即 Fever Time：客户端时段升到 3 时播 `feverStart.swf`，`rush_started=true` 时挂 fever 粒子。asset_names 按出现过的时段逐一声明 `background<id>_<tz>`。

**已落地（重建值）**：`battle_timezone.go` 逐场随机——开局黄昏 25%、夜晚 10%，之后每波 20% 推进一档（不回退）；金币/资材倍率取整为朝 1.0 / 夕 1.2 / 夜 2.0，写进 appear_table 与会话快照。概率可用 `MERCD35_BATTLE_DUSK_RATE` / `MERCD35_BATTLE_FEVER_RATE` / `MERCD35_BATTLE_TIME_ADVANCE_RATE` 调整，三项全 0 恢复全程白天。原服 `rush_mode`/`rush_count` 计数与时间推进规则未还原。
