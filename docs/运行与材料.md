# 运行与材料

## 服务端

推荐先在仓库根执行 `make env`，编辑 `.env` 后执行 `make run`。变量、优先级和相对路径说明见[仓库入口](../README.md#环境配置)。下面为绕过环境文件、直接指定参数的示例；若要完全忽略默认环境文件，应自行选择一个空的环境文件。

```sh
make build
./output/rebuilt/mercd35 -addr 127.0.0.1:18091 -server-host 127.0.0.1:18091 \
  -assets server/assets/cn350 -cards server/assets/shared/cards \
  -state server/server-state-cn35 -remote-assets inputs/files
```

LAN 运行时按自己的网络同时修改监听地址与 server-host。只读诊断为 /mercd/health、/mercd/routes、/mercd/unknown-endpoints 和 /cn35/assets/remote，没有管理令牌参数。服务端面向本地／自行部署环境。

保留全部 SQL 历史，包括早期空置表；不要按表名删除迁移。已有玩家库升级前先做一致性备份，恢复配对二进制与新 state 目录。未准备 stories 时章节列表为空；需要故事阅读者自行将合规取得的故事 fixture 放入 server/assets/cn350/stories/，不要提交。

## 客户端构建入口

将匹配的原包放进 inputs/apk/，用 `python3 client/prepare.py --mode server --server-host 127.0.0.1:18091` 校验、解码到 client/decoded、调整 Manifest 包名与服务地址。脚本拒绝覆盖已存在的解码目录。然后运行 `client/build.sh`；加 --sign 时按脚本要求设置自己的签名环境变量。

单机模式使用 `prepare.py --mode standalone`，再在 server/ 中执行 `gomobile bind -target=android/arm -androidapi 21 -o /tmp/mercd35.aar ./mobile`；`AAR=/tmp/mercd35.aar client/android-bootstrap/build.sh` 编译原创引导器并并入自备 inputs/files，最后按脚本输出的 CLIENT_SOURCE_DIR 执行 client/build.sh。仅使用 ARM32，与原客户端 ABI 配套。

单机资源在安装后的**首次启动**准备，安装器本身不会运行解压代码。`BootActivity` 显示进度，`BootProvider` 从 `assets/unity/` 将 bundle 原样复制到应用私有 `files/` 根目录（例如 `files/unit/unit_414.Android.unity3d`），并合并 `files/local_md5_v3.json`。文件复制与 MD5 校验完成后才写入索引、启动 Go 服务并进入 Unity。后续启动按索引和文件大小跳过已就绪文件，缺失项自动补齐；相同大小的外部损坏不在快速检查范围内。

清单合并脚本生成带 MD5 前 8 位的资源清单及 `assets/backend/local-assets.json`；客户端匹配本地 MD5 和文件存在性后走 `file://`，无需从 Go 的 remote_assets 下载 bundle。Go 仍提供业务、asset_info、app_conf 等接口；mobile 使用独立空目录 `assets/cn350/offline-empty` 隔离旧 `state/remote_assets`，不会删除旧资源或玩家 SQLite。升级必须重新生成 AAR 和 staging，不可复用旧 AAR。

`REMOTE_ASSETS_DIR` 可覆盖自备资源目录，支持直接包含 `unit/area/common` 的目录以及外套一层 `files/` 的形式。资源缺失、非法 bundle、符号链接会终止打包。新增及替换资源会重新计算 MD5，清单版本取当前毫秒时间与旧版本加一的较大值。每次启动仅使资源清单缓存失效，保留其他本地索引键及存档。

原作观测：匹配基线 SHA-256 的 CN3.5 DLL 中，`AssetResources.LoadAssetBundle` 比较清单 MD5 与 `LocalRecodMd5`，命中后通过 `GetBundlePersistentUrl` 读取 `Application.persistentDataPath/<逻辑名>.Android.unity3d`；`LocalRecodMd5` 使用普通 JSON 字符串映射。`common/bg-map`、`bg_message`、`bg_shout` 有客户端文件名过滤，清单生成按实际过滤后的文件计算哈希。原 DLL 保持不变。Unity 原生库可见 `getFilesDir` 路径接口；本实现使用 `Context.getFilesDir()`，该目录与目标设备 `persistentDataPath` 的一致性仍需冷启动日志实证。

重建实现：启动等待页、原子文件替换、缓存预置均为本仓库新增。资源仍在 APK 内保留一份，解压后另占一份存储空间。自动检查为 `python3 -m unittest discover -s client -p 'test_*.py'`；设备验收应确认 `local assets ready`、第二次 `copied=0`、业务正常且无 bundle HTTP 下载，最后检查 `Page Load Done : Top` 与重启存档。

单机清单合并脚本只处理文件名、类型元数据、哈希与索引，不解密资源。缺少资源仍会导致相关玩法不可用。客户端准备、AAR、签名与实机链尚未验收；本说明是构建入口，不表示已验证可在所有设备运行。

## 验证

`make check` 执行服务端 vet/test；`make api` 从实际路由导出文档。客户端需另做完整性、签名、冷启动、教程、核心玩法和重启存档验证。源码的来源标注与实现边界保留，不能把静态读取链或服务端测试结果提升为完整游戏实机验收。
